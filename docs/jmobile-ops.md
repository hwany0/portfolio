# J-Mobile 운영 및 보안 대응 사례

## 개요
- 본 문서는 J-Custom과 별개로, J-Mobile 환경에서 수행한 모바일 수금관리 운영, 보안 강화, 사용자 경험 개선 사례를 정리한 문서입니다.
- J-Mobile은 현장 수금/배달/고객 관리 업무를 지원하는 모바일 웹앱 기반 서비스로, 사용자 접근 제어와 실시간 업무 처리 흐름이 핵심입니다.
- 본 문서는 기능 구현뿐 아니라 보안, 개인정보 보호, 운영 편의성, 모바일 업무 체감 개선까지 함께 고려한 실무 경험을 정리합니다.

---

## 1. 모바일 수금관리 재구축 및 고도화

### 배경
- 기존 APP 개발 업체의 도산으로 유지보수가 어려워진 모바일 수금관리 시스템이 있었고, 운영상 유지보수와 업무 연속성 문제가 발생했습니다.
- 현장 수금 업무는 카드 결제, 배달 현황, 고객 검색, VOC 처리 등 실시간성이 매우 중요했습니다.

### 대응 내용
- 기존 APP + WEB 구조를 하이브리드 웹앱 기반으로 재구축했습니다.
- 결제 요청 상태, 승인 결과, 최종 처리 상태를 분리해 운영자가 각 단계의 흐름을 명확히 확인할 수 있도록 구성했습니다.
- 카드 결제 승인 과정에서 발생할 수 있는 응답 누락, 중복 처리, 상태 불일치 리스크를 방어하는 로직을 정리했습니다.
- 배달 현황 집계, VOC 사진 첨부, 사용자 로그인 현황, 모바일 공지사항 푸시 기능 등 현장 업무에 필요한 기능을 추가했습니다.
- Firebase FCM 기반 공지/알림 흐름을 적용해 운영 공지사항과 중요 알림을 전달했습니다.

### 효과
- 모바일 수금 업무의 유지보수성과 안정성을 높였습니다.
- 결제 상태 누락을 사전에 방지하고, 운영자가 상태를 빠르게 확인할 수 있게 되었습니다.
- 현장 업무 효율성과 실시간 가시성을 개선하며, 반복 수기 보완 업무를 줄였습니다.

---

## 2. 보안 및 개인정보 보호 강화

### 문제 상황
- 모바일 업무 시스템은 사용자 정보 접근 범위와 보안 수준이 매우 중요했습니다.
- 사용자별 개인정보 노출 위험, 접근 권한 불명확성, Native 앱과 WebView 간 검증 흐름의 보안 편차가 운영 리스크로 작용할 수 있었습니다.
- 특히 `IDOR(Insecure Direct Object Reference)`와 같은 구조적 문제를 점검해야 했습니다.

### 대응 내용
- 사용자 정보 노출 위험성과 접근 제어 구조를 점검하고, 사용자별 접근 범위를 명확히 정리했습니다.
- 개인정보 보호를 위한 서비스 보안 강화 방안을 검토하고 적용했습니다.
- Native 앱과 WebView 환경에서 동일한 사용자 식별 검증 및 권한 검증 기준을 적용하도록 보완했습니다.
- DB 및 API 레벨에서 민감 데이터 접근 범위를 분리하고, 사용자 식별값의 직접 접근 흐름을 정비했습니다.
- OWASP 관점에서 모바일 서비스의 보안 점검 항목을 정리하고 운영 기준으로 반영했습니다.

### 효과
- 사용자별 정보 접근 범위를 제한하여 민감 데이터 노출 위험을 낮췄습니다.
- 보안 취약점 식별과 대응 속도를 높였고, 개인정보 보호 수준을 개선했습니다.
- J-Mobile 운영 환경에서 보안 기준과 정책을 실무적으로 정립할 수 있었습니다.

## 3. 음성인식 + AI 기반 Direct Routing 프로세스 구축

### 배경
- 특정 독자 조회 및 업무 처리를 위해 사용자가 여러 메뉴를 순차적으로 이동해야 하는 불편함이 있었습니다.
- 예를 들어 아파트 검색 → 동 선택 → 아파트 독자 선택 → 수금 처리 / VOC 등록 과정에서 입력 부담과 탐색 비용이 컸습니다.
- 사용자 경험을 개선하기 위해, 어느 메뉴에서나 접근 가능한 플로팅 버튼과 음성 기반 Direct Routing 구조를 함께 도입해야 했습니다.

### 목표
- 사용자 음성 한 번으로 특정 고객/독자 조회와 세부 업무(수금, VOC, 상세 조회 등)를 바로 연결시키는 흐름을 구성
- 메뉴 탐색 경로를 줄이고, 필수 파라미터 누락 시 단계적으로 보완하는 구조로 사용자 실수를 줄임
- AI를 활용해 메뉴 식별, 파라미터 추출, 추천 후보 생성, 권한 검증까지 통합 운영할 수 있는 구조를 설계

### 핵심 구성
- 음성 입력을 받아 사용자 의도를 분석하는 LLM 기반 라우팅 엔진
- `MenuMetaCacheService`를 통해 메뉴 메타 정보를 메모리 캐시로 관리해 런타임 응답 속도 향상
- `VoiceParamResolver`와 `ParamProvider`를 활용해 메뉴별 파라미터 변환/추천 로직을 분리
- 필수 파라미터가 누락된 경우 `VoiceContext` 기반 재입력 흐름을 유지
- `MenuPermissionService`를 통해 사용자 권한 검증 후 접근 허용
- 비동기 로깅을 통해 실제 라우팅 성공/실패 사례를 축적하여 운영 개선 데이터로 활용

### 구현 포인트
- `vLLM API` 기반 `Gemma-4` 모델을 활용해 사용자 음성을 분석하고, 메뉴 ID, 액션, 파라미터를 추출했습니다.
- 메뉴별 파라미터를 메타 정보로 관리하면서, prompt 안에 메뉴/파라미터 예시를 포함해 LLM의 의도 파악 정합성을 높였습니다.
- 필수 파라미터 누락 시에는 다시 질문하도록 설계하고, 추천 후보가 있는 경우 유사한 값을 제안해 업무 연속성을 유지했습니다.
- AI Deep Link와 사용자 맥락 기반 화면 이동 구조를 함께 설계해, 음성 인식 결과를 실제 업무 화면으로 바로 연결할 수 있도록 구성했습니다.
- `VoiceResponse`는 `NAVIGATE`, `MISSING_PARAMS`, `RECOMMEND`, `SUMMARY`, `UNKNOWN` 등 상태 기반 구조로 설계하여 UI가 응답 상태에 따라 적절한 동작을 수행하도록 구성했습니다.
- 화면 측에는 FAB 기반 음성 버튼과 채팅형 인터페이스를 함께 두어, 익숙하지 않은 사용자가 쉽게 접근할 수 있도록 UX를 보완했습니다.

### 효과
- 특정 메뉴 탐색을 줄여 현장 업무 처리 시간이 단축되었습니다.
- 고령 사용자와 비숙련 사용자의 입력 부담을 완화하면서 업무 접근성을 높였습니다.
- 음성 입력에 대해 추천 후보와 재질문 구조를 두어 실패 시에도 사용자 흐름을 유지할 수 있었습니다.
- AI Deep Link와 사용자 맥락 기반 화면 이동을 함께 적용해 실제 업무 흐름을 한 번의 음성 입력으로 마무리할 수 있었습니다.
- 권한 검증, 비동기 로그, 파라미터 추천 로직을 함께 두어 운영 안정성과 추후 개선 가능성을 높였습니다.

---

## 4. 포트폴리오에서의 의미
- J-Mobile은 단순 모바일 화면 개발이 아니라, 실시간 수금/배달/고객 관리, 보안, 사용자 접근 제어, 운영 지원을 함께 다루는 시스템입니다.
- 모바일 운영 환경에서는 화면 개발 역량만큼이나 보안, 데이터 보호, 업무 흐름 설계가 중요합니다.
- 본 문서는 J-Mobile의 실제 운영 환경을 기술, 보안, 사용자 경험의 세 축으로 정리한 사례집입니다.

---

## 5. 정리
- J-Mobile은 J-Custom과 성격이 다른 모바일 업무 시스템이므로, 포트폴리오에서도 별도 문서로 분리해 관리하는 것이 정확합니다.
- 실제로는 수금/배달/결제/보안/사용자 경험을 함께 다루는 업무 환경이므로, 이를 개별 프로젝트 문서가 아니라 운영 문서로 구분해 보이는 것이 설득력이 높습니다.
