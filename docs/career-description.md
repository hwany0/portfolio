# 경력기술서

## 1. 경력 요약

**콘텐트리중앙 | 미디어개발팀 | 풀스택 개발자 | 2019.06 ~ 현재**

고객관리·구독·청구·수금·결제·멤버십 업무 시스템을 개발하고 운영했습니다. Java/Spring 기반 백엔드와 외부 API 연동을 중심으로 인증·인가, 배치 처리, 데이터 정합성 관리, 레거시 시스템 전환 및 운영 장애 분석을 수행했습니다.

주요 경험은 다음과 같습니다.

- 외부 결제·수금 API 연동 및 상태 관리·배치 자동화
- 매체사별 도메인 환경에서의 통합 인증, 토큰 재발급, MFA 구현
- 기존 업무 흐름을 고려한 레거시 전환과 공통 구조 정비
- 운영 중 발생한 API 오류, 직렬화 문제, 데이터 불일치의 재현 및 원인 분석
- 음성 인식 및 LLM/vLLM을 활용한 업무 메뉴 Direct Routing 구조 설계
- Java 17/Spring Boot 3.5.x 기반 현대화 프로젝트의 공통 설정·응답·예외·인가 구조 정비

## 2. 주요 프로젝트

### 2.1 옥외 광고 청약 시스템 SaaS 전환 및 공통 아키텍처 정비

- **기간:** 2026.09 ~ 진행 중
- **역할:** 백엔드 공통 구조 정비, 레거시 전환, 인증/인가 구조 설계 및 구현
- **기술:** Java 17, Spring Boot 3.5.x, Gradle, MyBatis, MSSQL, Thymeleaf

#### 배경 및 목표

기존 Java 8/Spring Framework 기반 업무 시스템을 Java 17/Spring Boot 3.5.x 기반으로 전환하고, 레거시 의존성을 줄이는 동시에 이후 기능 개발에서 공통 처리 방식을 일관되게 사용할 수 있는 기반을 마련하고 있습니다.

#### 수행 내용

- Java 17 및 Spring Boot 3.5.x 기반 실행 구조를 구성하고 Gradle/JAR 중심 빌드 구조로 정비
- 기존 전자정부프레임워크 의존성을 확인하고 Spring Boot 표준 구성으로 대체하는 작업 진행
- JSP 화면을 Thymeleaf로 전환하기 위한 공통 렌더링 구조와 화면 데이터 제공 방식 정비
- API 응답 DTO와 전역 예외 처리 구조를 표준화해 Controller별 반복 처리를 줄이는 방향으로 구성
- 조직 권한, 매체 권한, 사용자 그룹 권한을 구분하고 AOP 기반 공통 권한 검증 구조 설계·적용 중
- 메뉴 표시 권한과 실제 API 데이터 접근 권한을 분리하고, 요청 매체 ID와 사용자 권한 범위를 검증하는 정책 정리

#### 기술적 고려 사항

- 업무 로직 전체를 한 번에 재작성하기보다 공통 설정과 요청 처리 기반부터 정비해 전환 범위를 통제
- 권한 종류별 정책을 분리해 모든 관리자 기능을 하나의 권한 조건으로 처리하지 않도록 설계
- 화면에서 메뉴를 숨기는 것과 서버에서 API 접근을 차단하는 것을 별도 보안 계층으로 취급

#### 진행 상태

진행 중인 프로젝트입니다. 전환 기반 및 공통 구조를 정비하고 있으며, 화면 전환 범위 확대와 권한 정책별 테스트 및 회귀 검증을 이어갈 예정입니다. 완료되지 않은 작업을 완료 성과로 표현하지 않습니다.

### 2.2 J-Mobile AI Direct Routing 프로세스 구축

- **기간:** 2025.09 ~ 2025.12
- **역할:** AI UX 및 서버 처리 흐름 설계
- **기술:** Java 7, Spring Framework 4.2.1, JSP, vLLM API, 음성 인식, JEUS, WebToB

#### 배경 및 목표

모바일 업무 시스템에서 특정 고객 조회나 수금·VOC 업무를 수행하려면 여러 메뉴를 이동해야 했습니다. 음성 명령을 통해 사용자가 원하는 업무 메뉴와 필요한 파라미터를 추론하고 해당 업무로 바로 진입할 수 있는 흐름을 설계했습니다.

#### 수행 내용

- 화면 어디에서나 음성 입력을 사용할 수 있도록 진입 UX와 처리 흐름 정리
- 메뉴·파라미터·행위 정보를 프롬프트에 전달해 LLM이 업무 의도와 파라미터를 추론하도록 구성
- 필수 파라미터가 누락된 경우 재질문하고 입력값을 보완하는 흐름 설계
- `VoiceParamResolver`와 `ParamProvider` 기반으로 메뉴별 파라미터 해석, 추천 후보 생성 및 실제 DB 검증 책임을 분리
- 사용자 권한을 검증하고 비동기 로그를 기록해 운영 추적이 가능하도록 구성

#### 주요 고려 사항

- LLM의 추론 결과를 그대로 업무 처리에 사용하지 않고, 파라미터 검증과 사용자 권한 확인을 별도 단계로 둠
- 메뉴별 파라미터 처리 방식을 분리해 업무별 요구사항을 확장할 수 있도록 구성
- 검색 결과가 없거나 필수값이 누락된 경우를 고려해 재질문·후보 제안 흐름을 설계

- MFA 인증이 완료되기 전과 완료된 이후의 로그인 상태를 구분해 접근 흐름을 구성

- **기간:** 2022.12 ~ 2023.04

#### 수행 내용

- 외부 API를 통한 청구 생성 및 납부 링크 발급

- 응답 누락이나 결과가 불명확한 상황에서 재확인할 수 있도록 운영 흐름 보완
- 대량 API 호출 오류, 필드 불일치, 외부 연동 장애 등 운영 이슈를 분석하고 개선

#### 주요 고려 사항

- API 호출 성공 여부와 실제 업무 처리 완료 여부를 구분해 상태를 확인

- 중복 처리와 상태 불일치 가능성을 고려해 데이터 정합성 확인 흐름을 보완

## 4. 정리

업무 시스템 개발과 운영 경험을 바탕으로 API 연동, 인증·인가, 데이터 정합성 및 장애 분석을 수행해 왔습니다. 최근에는 레거시 시스템의 현대화와 공통 아키텍처 정비, LLM을 활용한 업무 UX 개선까지 경험 범위를 넓히고 있습니다.

**작성 시 유의:** 이 문서는 기존 포트폴리오에 기재된 내용을 바탕으로 작성한 초안입니다. 실제 지원 전에는 프로젝트별 역할 범위, 기간, 기술 버전 및 완료 상태를 다시 확인하고, 확인되지 않은 수치 성과는 추가하지 않습니다.
